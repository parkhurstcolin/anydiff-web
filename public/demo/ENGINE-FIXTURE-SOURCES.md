# Fixture sources

Every fixture in this directory is synthetic (generated by repo code) unless a
row below records its source URL.

| File | Source | License |
|---|---|---|

| `ghg_national_2022_m2_industry.xlsx` | https://github.com/DecarbNexus/useeio_ghg_sources_disaggregation/releases/download/v1.1/GHG_national_2022_m2_industry.xlsx (EPA-useeio-derived GHG workbook, fetched 2026-10-29) | MIT |

`washinvestments.xlsx` note: its `xl/worksheets/sheet1.xml` declares `<dimension ref="A1"/>`
while actually holding 1,873 rows / 43k cells, and `xl/_rels` points at a missing
`xl/drawings/drawing1.xml` (non-`read_only` openpyxl raises `KeyError` on it).
Both are exercised by `tests/test_realworld_fixtures.py`.

`Q3-forecast.xlsx` / `Q3-forecast-v2.xlsx`: the day-1 "created" demo pair,
regenerable with `uv run python tests/fixtures/generate_q3_forecast.py`.
v2 differs from v1 only by `Sheet2!B14: 4200000 -> 4800000` (+14%) and a new
column F "contingency" (header + 12 values); `tests/test_q3_forecast_demo.py`
pins the BRIEF demo line `Sheet2!B14: 4.2M -> 4.8M`.

`meeting-notes.docx` / `meeting-notes-v2.docx` / `meeting-notes-tracked.docx`
/ `meeting-notes-moved.docx`: the day-2 DOCX fixtures, hand-written
WordprocessingML regenerated with
`uv run python tests/fixtures/generate_docx_fixtures.py` (stdlib zipfile, no
generator library involved; output is content-deterministic but NOT
byte-deterministic — zip entries carry wall-clock timestamps, measured
pass-8: regenerating rewrites every entry's mtime, so re-run it only when
changing the fixtures on purpose). v2 differs from v1 by
exactly three intentional changes (re-titled `Heading1` ¶1, edited ¶3,
inserted budget-table row "Contingency"); the tracked variant carries the ¶3
edit as `w:del`/`w:ins` revisions and the moved variant carries the ¶2
paragraph as a pending `w:moveFrom`/`w:moveTo` revision (pass-8 review: the
original two-marker refusal let it through) — both must be refused with exit
2. `tests/test_docx_diff.py` pins all of it.

`nested-tables.docx` / `nested-tables-v2.docx`: the pass-21 pair for known
issue 2, same generator and same determinism caveats as the meeting-notes
family — an outer table whose first cell holds a paragraph AND its own
table (WordprocessingML table-in-a-cell). v2 differs by exactly ONE nested
cell (`4.2M -> 4.8M`); before nested content flowed into the containing
cell's string this pair diffed as ZERO changes. `tests/test_docx_diff.py`
pins the extraction, the one-line diff and the CLI output.

`deck.pptx` / `deck-v2.pptx` / `identical.pptx`: the day-3 PPTX fixtures,
generated with `uv run python tests/fixtures/generate_pptx_fixtures.py`
(python-pptx, a DEV dependency; the product reads PPTX with stdlib only;
the two embedded PNGs are hand-built via stdlib zlib/struct — no third-party
assets). v2 differs from v1 by exactly four intentional changes: the "Risks"
slide moved from position 4 to 2, the "Market" slide's image swapped for
different bytes (detected via content hash), one "Next steps" text edit, and
speaker notes added to "Revenue". Slide 6 "Pipeline" (title + 3x3 table) is
identical in both decks and must produce zero diff noise (pass 9: table
extraction). `identical.pptx` is `deck.pptx` re-zipped (same part content,
stored uncompressed with fresh timestamps) and must diff to zero changes.

`budget-tables.pptx` / `budget-tables-v2.pptx`: the pass-9 zero-false-negative
pair, same generator — one BLANK slide whose only content is a 4x3 table;
v2 changes exactly one cell (EMEA Q3 `4.2M -> 4.8M`). Before table
(graphicFrame `a:tbl`) extraction this pair diffed as ZERO changes; it must
now print exactly one `row` change. `tests/test_pptx_diff.py` pins all of it.

`chart-trend.pptx` / `chart-trend-v2.pptx`: the pass-22 zero-false-negative
pair for known issue 1, same generator — one BLANK slide whose only content
is a clustered-column chart (2 cached series x 3 categories); v2 changes
exactly one cached value (`"Q3 revenue"` Sep `4.8 -> 5.1`). python-pptx
also embeds an xlsx behind `c:externalData`; the product never reads it —
the `c:numCache`/`c:strCache` values are what PowerPoint itself renders.
Before cached chart-series extraction this pair diffed as ZERO changes; it
must now print exactly one `row` change
(`Slide 1 Chart 1 row 3: Q3 revenue | Sep | 4.8 -> Q3 revenue | Sep | 5.1`).
`tests/test_pptx_diff.py` pins extraction, the one-line diff and the CLI.

`external-link.pptx` / `external-link-v2.pptx`: the pass-23
zero-false-negative pair for known issue 3, also written by
`generate_pptx_fixtures.py` — but hand-built minimal OOXML via stdlib
zipfile (python-pptx cannot express an external image target), same
content-deterministic-not-byte-deterministic caveat as the DOCX family.
One slide, a title and a `p:pic` whose `r:embed` rel is
`TargetMode="External"` (no media bytes in either package); v1 and v2
differ ONLY in the linked URL (`q3-map.png` -> `q4-map.png`, fictional
example.com targets, never fetched). Before the `media_unresolved` flag
this pair diffed as ZERO changes; it must now print exactly one
`image cannot be resolved` line, and each side's self-diff must show that
same honest line (unreadable media cannot be confirmed unchanged).
`tests/test_pptx_diff.py` pins all of it.

`q3-report.pdf` / `q3-report-v2.pdf` / `q3-report-inserted.pdf`: the day-4
created PDF fixtures, regenerated with
`uv run python tests/fixtures/generate_pdf_fixtures.py` — a minimal valid
PDF written by hand (stdlib only, no writer library) and byte-deterministic
(content-only, no timestamps). v2 differs from the base by exactly TWO
intentional changes, both on page 3: a number-only edit (`4.2M -> 4.8M`,
must carry the `number changed` note) and a words edit on the next line
(must NOT). `inserted` adds a new page 2, renumbering pages 3-4: the diff
must be ONE `page added` line with zero move noise. `tests/test_pdf_diff.py`
pins it. `rfc9315.pdf` (table above) supplies the real-world side: 23 pages
from a real XML-to-PDF toolchain, and a comment appended after `%%EOF` must
diff to zero (`tests/test_realworld_pdf.py`, which also pins
cross-call extraction determinism).

`diagram.png` / `diagram-edited.png` / `diagram-reencoded.png`: the day-4
PNG fixtures, regenerated with `uv run python tests/fixtures/generate_png_fixtures.py`
(pillow, drawn rectangles — no third-party assets). The edited twin grows
the last bar (exactly one intentional change; region `(180,40) 21x50 px`,
2.73%); the re-encoded twin is the base decoded and re-saved with different
PNG metadata — byte-different file, pixel-identical content, must diff to
ZERO changes (`tests/test_png_diff.py`).
